# Sesión 2026-06-16 — Mainline: display + USB resueltos

Dos hitos grandes del bring-up de mainline (Linux 7.0.12) en el BQ Aquaris E4.5
(MT6582 "krillin"):

## M3 — display (ver mainline/HITO-M3-DISPLAY-RESUELTO.md)
El amarillo era un **desajuste de formato**: simplefb escribía `a8r8g8b8` (32bpp) y
el OVL leía `RGB565` (16bpp) → se perdía el azul → blanco→amarillo. Fix: DT
`r5g6b5/stride1088` + reprogramar el OVL clonando la config DISP exacta de pmOS
(leída por /dev/mem). Clave: el MUTEX (`MOD=0x680/SOF=1/EN=0x303`) es el commit.

## M2b — USB (ver mainline/HITO-M2b-USB-RESUELTO.md)
Tres bugs encadenados en `mt6582-musb.c`:
1. `L1INTM=0x1ff` habilitaba IRQs L1 no atendidas → "irq 26: nobody cared" → IRQ
   deshabilitada. Fix: `L1INTM = TX|RX|USBCOM`.
2. PHY dejaba los pull-downs activos → D+ no subía. Fix: portar `usb_phy_recover()`
   completo (liberar pull-downs/forces + VBUSSCMP_EN).
3. El teléfono no levantaba `usb0`. Fix: configurarlo por `ioctl` en el init.
Resultado: `g_ether` enumera, `ping 172.16.42.1` 0% loss.

## Artefactos clave (en la Pi cpcd@192.168.0.38, ~/mainline)
- Driver: `linux-7.0.12/drivers/usb/musb/mt6582-musb.c` (v16)
- DT: `linux-7.0.12/arch/arm/boot/dts/mediatek/mt6582-bq-krillin.dts` (simplefb r5g6b5 + usb node)
- Init de pruebas: `pkg/tiny_init_m3v3.c` (display), `pkg/tiny_init_m2b.c` (display + usb0)
- Imágenes: `pkg/boot-mainline-m2b.img` (kernel v16 + init m2b)
